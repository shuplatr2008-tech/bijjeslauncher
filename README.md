# BijjesLauncher

Сайт незалежного лаунчера Minecraft. Статична сторінка українською, адаптована для комп’ютерів і телефонів. Сайт не використовує сторонніх трекерів, шрифтів або сервера для обробки форм.

## Завантаження

Перший випуск: **1.0.0**, **macOS Apple Silicon**. Інсталятор: `BijjesLauncher-1.0.0-arm64.dmg`. Windows, Linux та Mac Intel поки не мають готових збірок. Вхід Microsoft у цьому випуску відсутній; профілі зберігаються локально. Цей випуск не підписаний і не нотаризований Apple.

Сайт не містить файлів гри Minecraft або Java. Гра й компоненти завантажуються самим лаунчером окремо. BijjesLauncher не є офіційним продуктом Minecraft і не пов’язаний із Mojang або Microsoft.

## Локальний перегляд

Скопіюй інсталятор у `downloads/BijjesLauncher-1.0.0-arm64.dmg`, після чого запусти в цій папці:

```sh
python3 -m http.server 4174 --bind 127.0.0.1
```

Відкрий `http://127.0.0.1:4174`. Сторінка працює і без JavaScript; він лише додає поточний рік та розмір файлу з `download.json`.

## Публікація на GitHub Pages

1. Використовуй окремий публічний репозиторій `bijjeslauncher`, основна гілка — `main`. Додавай у нього вміст саме цієї папки, а не приватні файли лаунчера чи користувацькі дані.
2. Створи GitHub Release із тегом `v1.0.0` та прикріпи готовий `BijjesLauncher-1.0.0-arm64.dmg`. SHA-256 і точний розмір записані у `download.json`. Папка `downloads/` виключена з Git, бо великий інсталятор розміщується в Releases.
3. У Settings → Pages вибери джерело **GitHub Actions**.
4. Запусти workflow **Publish BijjesLauncher website**. Він перевіряє доступність інсталятора, підставляє посилання на нього та публікує сайт. Якщо реліз недоступний, публікація зупиняється, щоб не створювати кнопку з непрацюючим посиланням.

Після публікації адреса має вигляд `https://<власник>.github.io/bijjeslauncher/`. Наявність файлів і workflow в репозиторії ще не означає, що сайт уже опублікований: потрібно перевірити успішне виконання Pages та саму адресу.

## Оновлення випуску

Онови версію, ім’я файлу й посилання в `index.html`, `.github/workflows/pages.yml` та `download.json`. Додай новий файл у Releases, тоді запускай публікацію. Значення `bytes` і `sha256` мають відповідати саме новому інсталятору.
